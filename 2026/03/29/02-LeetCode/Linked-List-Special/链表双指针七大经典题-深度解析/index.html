🧠 核心知识：Python链表的底层真相

在开始刷题前，必须理解Python处理链表的特殊性，这直接决定了为什么我们会犯某些错误：

1. 非连续内存

不同于Python的list（底层是动态数组，内存连续），链表节点在内存中是离散的。每个节点是一个对象，通过next属性存储另一个对象的引用（内存地址）。

2. 引用即指针

在Python中，执行p = head并不是复制了链表，而是让变量p指向了head所指向的内存地址。

3. 垃圾回收机制(GC)

Python使用引用计数。当我们执行p.next = None时，如果该节点没有其他引用，它才会被真正释放。这也是为什么”断开原链表指针”是链表题目中最容易忽略的性能与逻辑陷阱。

方法 时间复杂度 空间复杂度 适用场景

分治合并 $O(N \log k)$ $O(\log k)$ 递归栈空间

📝 链表Checklist：提交前自查

在提交链表题目前，请按此清单检查：

✅ 基础检查

  1. 空链表处理：if not head: return None
  2. 单个节点处理：特殊逻辑是否正确
  3. 返回值：是否正确返回头结点

✅ 指针操作检查

  1. 虚拟头结点：是否需要使用dummy？
  2. 指针移动：curr = curr.next是否在正确时机？
  3. 边界条件：while循环条件是否正确？
    • while curr: vs while curr.next:
    • while fast and fast.next:

✅ 内存与连接检查

  1. 节点断开：移动节点时是否断开原连接？
  2. 环检测：是否会意外创建环？
  3. 尾节点：尾节点的next是否为None？

✅ 特殊场景检查

  1. 删除头结点：是否能正确处理？
  2. 全链表删除：是否会返回None？
  3. 负数/越界：输入参数是否合法？

✅ 性能检查

  1. 时间复杂度：是否最优？
  2. 空间复杂度：是否使用额外空间？
  3. 递归深度：是否会栈溢出？
