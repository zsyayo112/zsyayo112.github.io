WEEK1 基础概念

Grep的使用 Grep 是 Unix/Linux 系统中最常用的文本搜索工具，名字来自 Global Regular Expression Print。

基本语法： grep [选项] 模式 文件

Grep的家族成员

grep -F(Fixed): 最快, 不解析正则， 只找死字符

grep -E(Extended): 最常用,支持 +, ?, |, ()

grep -P(Perl): 最强,支持”断言”(Lookahead) 等高级用法

🚀 UNSW COMP9044/2041 Week 01 正则表达式速查表 (Cheat Sheet)

1. 核心工具指令 (Grep Family)

命令 全称 用途 核心笔记
grep -F Fixed String 纯字符串匹配 速度最快。不解析正则，用于找 $ 或 * 等原义字符。
grep -E Extended Regex 扩展正则匹配 最常用。支持 +, ?, `
grep -P Perl Regex 强力正则匹配 支持断言 (Lookahead)，用于处理 -E 搞不定的复杂逻辑。
grep -i Ignore Case 忽略大小写 匹配 COMP 时也能匹配 comp。
grep -v Invert Match 反向选择 打印不匹配正则的所有行（排除法）。
grep -w Word Regexp 全词匹配 相当于在正则前后自动加了 \b。

2. 经典实战匹配 (Tutorial 案例精选)

目标对象 推荐正则表达式 (ERE) 核心逻辑解析
UNSW 课程代码 \b[a-zA-Z]{4}[0-9]{4}\b \b 确保独立单词；{4} 锁定 4 字母 + 4 数字。
IP 地址 (1-25) 129\.94\.172\.([1-9]|1[0-9]|2[0-5]) \. 转义点号；() 分支匹配末尾数字范围。
十六进制颜色 ^#([0-9a-fA-F]{6}|[0-9a-fA-F]{3})$ ^$ 锁定整行；支持 CSS 标准的 3 位或 6 位。
C 预处理器 ^\s*#\s*[a-zA-Z_] ^\s* 允许井号前有空格；匹配合法标识符开头。
正实数 (行首) ^[0-9]+(\.[0-9]*)? + 至少一位整数；(\.)? 小数部分及其点号可选。
空行 ^$ 或 ^\s*$ 前者匹配纯空行，后者匹配包含空格/Tab 的“视觉空行”。

3. 三个“保命”避坑准则 (Best Practices)

  1. 引号护体：
    在 Shell (bash/zsh) 中运行 grep 时，必须使用单引号包裹正则，防止元字符（如 *, |, $）被 Shell 提前解析。

    ✅ grep -E '^[A-Z]{4}'
    ❌ grep -E ^[A-Z]{4}

  2. 边界锚点的重要性：

    • ^ 和 $：锁定整行的开始和结束。
    • \b：锁定单词的边界。防止匹配到长单词中的片段（如防止 is 匹配到 th**is**）。

  3. 非贪婪逻辑：
    .* 是贪婪的，会吃掉尽可能多的内容。在匹配 HTML 标签或引号内容时，优先考虑“排除法”：

    • 匹配引号内容："[^"]*" (比 ".*" 更精准)
    • 匹配 HTML 标签：<[^>]*> (防止吞掉整行标签)

4. 常用元字符快速回顾

  • . : 匹配除换行符外的任意单个字符。
  • * : 匹配前一个字符 0 次或多次。
  • + : 匹配前一个字符 1 次或多次。
  • ? : 匹配前一个字符 0 次或 1 次。
  • | : 逻辑“或”（Alternation）。
  • () : 分组，用于限定 | 的范围或重复一段模式。

深度理解（避坑指南）

  1. 贪婪匹配 vs. 非贪婪匹配

笔记： .* 会匹配尽可能多的字符
例子： 匹配HTML 标签 test

如果使用 <.*> 他会匹配第一个 < 到 > 之间的所有字符

解决方案: 如果使用[^>]*。 意思是匹配除了 > 以外的所有字符， 知道遇到第一个 > w 为止

正确练习 ：

<[^>]*>

  1. shell的特殊字符

为什么 grep <p> test.html 会报错：

< > 是shell里面的重定向符号
准则： 永远用单引号扩起你的正则表达式

错误：
grep <p>|<br> file

正确：
grep -E '<p>|<br>' file

❌ 错误原因分析

第一阶段：```grep -E -i -w ‘[a-z]{4}[0-9]{4}’:``

它在 raw_data.txt 中找到了包含课程代码（如 COMP9044）的整行数据。

输出的内容长这样：z5523839 | COMP9044 | 85 | 2026-03-01。

第二阶段：| grep -E '^z[0-9]{7}$'

这一步是在上一步的结果中搜索。

关键点：^ 表示行首，$ 表示行尾。

你的正则要求整行只能有 z 加 7 位数字（比如 z5523839），不能有任何其他东西。

冲突： 上一步输出的行里有 | COMP9044 | … 等一大串字符。所以第二条 grep 发现这一行并不匹配 ^z[0-9]{7}$（因为它太长了，结尾不是数字而是日期），于是把所有结果都过滤掉了。

第二个疑问：但是grep的正则不是贪心匹配吗 难道不会匹配含有该表达式的所有行？

这是一个非常经典的学习误区，咱们得赶紧把这个概念理顺！你提到的“贪婪匹配”和“匹配含有该表达式的所有行”其实是两码事。

这里的核心矛盾在于：正则表达式的“贪婪性”控制的是“匹配多长”，而 ^ 和 $ 控制的是“匹配位置”。

1. 为什么 ^ 和 $ 锁死了你的结果？:

当你写 grep -E ‘^z[0-9]{7}$’ 时，你是在对 grep 下达一个极度严格的指令：

“给我找这样的一行：它必须以 z 开头，后面跟着 7 个数字，然后立刻结束。”

你的数据行：z5523839 | COMP9044 | 85 | 2026-03-01

正则的要求：z5523839 (到此为止，后面必须是行尾)

冲突点：实际行在 z5523839 后面还有一个空格、一个竖线、课程代码等等。

结论：因为这一行**不符合“在数字后立刻结束”**这个条件，所以 grep 判定这一行不匹配。

正则的匹配是“全有或全无”的逻辑：如果加上了 ^ 和 $，它就从“包含检查”变成了“格式校验”。

2. 什么是真正的“贪婪匹配” (Greedy Matching)？

“贪婪”通常指的是量词（如 * 或 +）的表现。它指的是：如果一个模式有多种匹配方式，它会抓取最长的那一个。

例子：假设有一行文本 内容

正则：<.*>

贪婪表现：它不会只匹配 ，它会一直匹配到最后一个 >，结果是 内容。这就是贪婪——它想“吃”得尽可能多。

但贪婪不能突破你设置的边界（Anchors）。如果你规定了 $（行尾），而数据还没结束，它就只能宣告匹配失败。

  1. 修正你的理解：grep 的默认行为
    如果你想表达“匹配含有该表达式的所有行”，你不应该加 ^ 和 $。

✅ grep -E ‘z[0-9]{7}’：
只要行里任何位置出现了 zID，这一行就会被抓出来。（这就是你想要的“匹配含有该表达式的行”）。

❌ grep -E ‘^z[0-9]{7}$’：
只有当这一行除了 zID 啥也没有时，才会被抓出来。

总结
正则定位符 (Anchors) vs 匹配内容：

pattern (无锚点)：只要行内包含 pattern 即可。

^pattern：行必须以 pattern 开头。

pattern$：行必须以 pattern 结尾。

^pattern$：整行必须精确等于 pattern，不能有任何余数。
