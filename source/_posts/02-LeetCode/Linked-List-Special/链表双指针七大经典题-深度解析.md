## 🧠 核心知识：Python链表的底层真相

在开始刷题前，必须理解Python处理链表的特殊性，这直接决定了为什么我们会犯某些错误：

### 1. 非连续内存
不同于Python的`list`（底层是动态数组，内存连续），链表节点在内存中是离散的。每个节点是一个对象，通过`next`属性存储另一个对象的引用（内存地址）。

```python
# 链表节点定义
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

### 2. 引用即指针
在Python中，执行`p = head`并不是复制了链表，而是让变量`p`指向了`head`所指向的内存地址。

```python
# 图示：引用关系
head → [val=1|next] → [val=2|next] → [val=3|next] → None
p ↗
# p和head指向同一个内存地址
```

### 3. 垃圾回收机制(GC)
Python使用引用计数。当我们执行`p.next = None`时，如果该节点没有其他引用，它才会被真正释放。这也是为什么"断开原链表指针"是链表题目中最容易忽略的性能与逻辑陷阱。

## 🎯 双指针技巧分类

### 第一板斧：虚拟头结点(Dummy Node) —— 边界消灭器

#### 适用题目：
- 21. 合并两个有序链表
- 23. 合并K个升序链表  
- 86. 分隔链表
- 19. 删除倒数第N个节点

#### 核心逻辑：
当需要创建新链表或头结点可能被删除/改变时，先创建一个`dummy = ListNode(-1)`。这样可以统一处理逻辑，避免繁琐的`if head is None`判断。

```python
def dummy_node_template(head):
    dummy = ListNode(-1)  # 创建虚拟头结点
    dummy.next = head     # 连接到原链表
    curr = dummy          # 工作指针
    
    # 统一处理逻辑，无需特殊判断头结点
    while curr.next:
        # 处理逻辑
        curr = curr.next
    
    return dummy.next     # 返回真正的头结点
```

#### 示意图：
```
原链表: head → [1] → [2] → [3] → None

创建dummy: dummy → [X] → head → [1] → [2] → [3] → None
                    ↑
                   curr起点

处理完成后: dummy → [X] → 新链表 → None
返回: dummy.next
```

### 第二板斧：快慢指针(Fast & Slow) —— 结构探测器

#### 适用题目：
- 876. 链表的中点
- 141. 环形链表
- 142. 环形链表II

#### 核心逻辑：
利用两个指针的速度差，在不计算链表长度的情况下探测链表的内部结构。

```python
def fast_slow_template(head):
    slow = fast = head
    
    # 关键：fast and fast.next 双重检查
    while fast and fast.next:
        slow = slow.next      # 慢指针走1步
        fast = fast.next.next # 快指针走2步
    
    return slow  # 慢指针所在位置
```

#### 三种变体：

**1. 找链表中点（876题）**
```
链表: [1] → [2] → [3] → [4] → [5] → None

步骤:
slow, fast都从1开始
1. slow=1, fast=1
2. slow=2, fast=3  (fast走2步)
3. slow=3, fast=5  (fast走2步)
4. fast.next为None，停止
结果: slow=3，即中点
```

**2. 检测环（141题）**
```
有环链表: [1] → [2] → [3] → [4] → [5] → [3] (回到3)

步骤:
slow, fast都从1开始
1. slow=1, fast=1
2. slow=2, fast=3
3. slow=3, fast=5
4. slow=4, fast=3
5. slow=5, fast=5  ← 相遇！说明有环
```

**3. 找环起点（142题）**
```
有环链表: [1] → [2] → [3] → [4] → [5] → [3] (环起点是3)

步骤:
1. 快慢指针找到相遇点(5)
2. 一个指针回head(1)，另一个在相遇点(5)
3. 同步走，每次1步
4. 再次相遇点就是环起点(3)
```

### 第三板斧：同步/步长差指针 —— 长度对齐器

#### 适用题目：
- 19. 删除倒数第N个节点
- 160. 相交链表
- LCR 140. 训练计划II

#### 核心逻辑：
通过调整指针的起始位置或步长，消除长度差异，实现同步操作。

**1. 删除倒数第N个节点（19题）**
```python
def remove_nth_from_end(head, n):
    dummy = ListNode(-1, head)  # 虚拟头结点是关键！
    fast = slow = dummy
    
    # fast先走n+1步
    for _ in range(n + 1):
        fast = fast.next
    
    # 同步走直到fast为None
    while fast:
        fast = fast.next
        slow = slow.next
    
    # 删除slow.next
    slow.next = slow.next.next
    
    return dummy.next
```

**示意图：**
```
链表: [1] → [2] → [3] → [4] → [5], n=2 (删除倒数第2个，即4)

dummy → [1] → [2] → [3] → [4] → [5]
 ↑slow   ↑fast(先走3步)

同步走:
fast=4, slow=2
fast=5, slow=3
fast=None, slow=4

删除slow.next: [3] → [5]
```

**2. 相交链表（160题）**
```python
def get_intersection_node(headA, headB):
    p1, p2 = headA, headB
    
    # 关键：p1走完A走B，p2走完B走A
    while p1 != p2:
        p1 = p1.next if p1 else headB
        p2 = p2.next if p2 else headA
    
    return p1  # 相遇点或None
```

**示意图：**
```
链表A: [A1] → [A2] → [C1] → [C2] → None
链表B: [B1] → [B2] → [B3] → [C1] → [C2] → None
交点: C1

p1路径: A1 → A2 → C1 → C2 → B1 → B2 → B3 → C1
p2路径: B1 → B2 → B3 → C1 → C2 → A1 → A2 → C1
在C1相遇！
```

## ⚠️ 避坑指南：实战错误复盘

在刷题过程中，我总结了三个必须刻在脑子里的错误：

### 🚨 错误1：忘记断开原链表的next指针 (LeetCode 86)

#### 错误代码：
```python
# 错误：直接连接，未断开原链接
p1.next = curr
p1 = p1.next
curr = curr.next  # 继续使用原链表的next
```

#### 问题分析：
在分解链表时，直接把原链表的节点接到新链表`p1.next = p`，但没有把`p.next`置空。

#### 后果：
结果链表的最后一个节点可能还带着原链表的"尾巴"，导致形成环或指向错误位置，程序死循环。

#### 正确做法：
```python
# 正确：先保存next，再断开连接
temp = curr.next  # 保存下一个节点
curr.next = None  # 断开当前节点的连接
p1.next = curr    # 连接到新链表
p1 = p1.next      # 移动指针
curr = temp       # 继续处理下一个节点
```

#### 教训：
只要移动原链表节点，养成先用`temp`保存`next`并立即置空`p.next`的习惯。

### 🚨 错误2：快指针步进时的AttributeError (LeetCode 876/141)

#### 错误代码：
```python
# 错误：可能访问None的next属性
while fast.next is not None:
    slow = slow.next
    fast = fast.next.next  # 如果fast为None，这里报错！
```

#### 问题分析：
如果链表为空或只有一个节点，`fast`可能是`None`，访问`.next`直接报错`AttributeError: 'NoneType' object has no attribute 'next'`。

#### 正确做法：
```python
# 正确：双重检查
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next  # 安全，因为fast和fast.next都不为None
```

#### 教训：
永远使用`while fast and fast.next:`，确保两步步进是安全的。

### 🚨 错误3：删除倒数第N个时的"越界" (LeetCode 19)

#### 错误代码：
```python
# 错误：试图找倒数第N+1个节点
fast = head
for _ in range(n + 1):  # 如果n=链表长度，这里会越界！
    fast = fast.next
```

#### 问题分析：
试图找倒数第`N+1`个节点来执行删除，但如果`N`正好是链表长度（删头结点），则`N+1`不存在。

#### 正确做法：
```python
# 正确：使用dummy节点
dummy = ListNode(-1, head)
fast = slow = dummy

# fast先走n+1步（从dummy开始，不会越界）
for _ in range(n + 1):
    fast = fast.next
```

#### 教训：
涉及删除操作，必须使用`dummy`节点。让`p2`从`dummy`开始走，确保能找到被删节点的前驱。

## 🏭 工业级Python实现示例

### 合并K个升序链表 (LeetCode 23)

针对LeetCode 23，利用Python的`heapq`库可以实现最优的$O(N \log k)$复杂度：

```python
import heapq
from typing import List, Optional

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        """
        合并K个升序链表
        
        时间复杂度: O(N log k)，其中N是总节点数，k是链表数量
        空间复杂度: O(k)，堆的大小
        
        思路:
        1. 使用最小堆维护每个链表的当前最小节点
        2. 每次从堆中弹出最小值，连接到结果链表
        3. 将被弹出节点的下一个节点加入堆中
        """
        # 创建虚拟头结点
        dummy = ListNode(-1)
        p = dummy
        
        # 初始化最小堆
        pq = []
        
        # 放入各链表头，增加i(index)是为了防止val相同时直接比较ListNode对象报错
        for i, head in enumerate(lists):
            if head:
                # (值, 索引, 节点) 三元组
                # 索引用于解决值相同时的比较问题
                heapq.heappush(pq, (head.val, i, head))
        
        # 不断从堆中取出最小值
        while pq:
            val, i, node = heapq.heappop(pq)
            p.next = node
            p = p.next
            
            # 如果该节点还有下一个节点，加入堆中
            if node.next:
                heapq.heappush(pq, (node.next.val, i, node.next))
        
        return dummy.next
```

#### 性能分析：
- **时间复杂度**：$O(N \log k)$
  - 每个节点进出堆一次：$O(N)$
  - 堆操作：$O(\log k)$
  - 总计：$O(N \log k)$
- **空间复杂度**：$O(k)$
  - 堆中最多存储k个节点

#### 对比其他方法：
| 方法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|------------|------------|----------|
| 逐一两两合并 | $O(kN)$ | $O(1)$ | k较小 |
| 堆合并 | $O(N \log k)$ | $O(k)$ | 通用最优 |
| 分治合并 | $O(N \log k)$ | $O(\log k)$ | 递归栈空间 |
