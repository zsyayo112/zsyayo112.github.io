## Grep的使用 Grep 是 Unix/Linux 系统中最常用的文本搜索工具，名字来自 Global Regular Expression Print。


基本语法： grep [选项] 模式 文件


### Grep的家族成员

grep -F(Fixed): 最快, 不解析正则， 只找死字符

grep -E(Extended): 最常用,支持 +, ?, |, ()

grep -P(Perl): 最强,支持"断言"(Lookahead) 等高级用法



# 🚀 UNSW COMP9044/2041 Week 01 正则表达式速查表 (Cheat Sheet)

### 1. 核心工具指令 (Grep Family)
| 命令 | 全称 | 用途 | 核心笔记 |
| :--- | :--- | :--- | :--- |
| `grep -F` | **Fixed String** | 纯字符串匹配 | **速度最快**。不解析正则，用于找 `$` 或 `*` 等原义字符。 |
| `grep -E` | **Extended Regex** | 扩展正则匹配 | **最常用**。支持 `+`, `?`, `|`, `{}`，是 Lab 和考试的首选。 |
| `grep -P` | **Perl Regex** | 强力正则匹配 | 支持**断言** (Lookahead)，用于处理 `-E` 搞不定的复杂逻辑。 |
| `grep -i` | **Ignore Case** | 忽略大小写 | 匹配 `COMP` 时也能匹配 `comp`。 |
| `grep -v` | **Invert Match** | 反向选择 | 打印**不匹配**正则的所有行（排除法）。 |
| `grep -w` | **Word Regexp** | 全词匹配 | 相当于在正则前后自动加了 `\b`。 |

### 2. 经典实战匹配 (Tutorial 案例精选)

| 目标对象 | 推荐正则表达式 (ERE) | 核心逻辑解析 |
| :--- | :--- | :--- |
| **UNSW 课程代码** | `\b[a-zA-Z]{4}[0-9]{4}\b` | `\b` 确保独立单词；`{4}` 锁定 4 字母 + 4 数字。 |
| **IP 地址 (1-25)** | `129\.94\.172\.([1-9]\|1[0-9]\|2[0-5])` | `\.` 转义点号；`()` 分支匹配末尾数字范围。 |
| **十六进制颜色** | `^#([0-9a-fA-F]{6}\|[0-9a-fA-F]{3})$` | `^$` 锁定整行；支持 CSS 标准的 3 位或 6 位。 |
| **C 预处理器** | `^\s*#\s*[a-zA-Z_]` | `^\s*` 允许井号前有空格；匹配合法标识符开头。 |
| **正实数 (行首)** | `^[0-9]+(\.[0-9]*)?` | `+` 至少一位整数；`(\.)?` 小数部分及其点号可选。 |
| **空行** | `^$` 或 `^\s*$` | 前者匹配纯空行，后者匹配包含空格/Tab 的“视觉空行”。 |

### 3. 三个“保命”避坑准则 (Best Practices)

1. **引号护体**：
   在 Shell (bash/zsh) 中运行 `grep` 时，**必须使用单引号**包裹正则，防止元字符（如 `*`, `|`, `$`）被 Shell 提前解析。
   > ✅ `grep -E '^[A-Z]{4}'`
   > ❌ `grep -E ^[A-Z]{4}`

2. **边界锚点的重要性**：
   - `^` 和 `$`：锁定**整行**的开始和结束。
   - `\b`：锁定**单词**的边界。防止匹配到长单词中的片段（如防止 `is` 匹配到 `th**is**`）。

3. **非贪婪逻辑**：
   `.*` 是贪婪的，会吃掉尽可能多的内容。在匹配 HTML 标签或引号内容时，优先考虑“排除法”：
   - 匹配引号内容：`"[^"]*"` (比 `".*"` 更精准)
   - 匹配 HTML 标签：`<[^>]*>` (防止吞掉整行标签)

---

### 4. 常用元字符快速回顾
- `.` : 匹配除换行符外的任意单个字符。
- `*` : 匹配前一个字符 0 次或多次。
- `+` : 匹配前一个字符 1 次或多次。
- `?` : 匹配前一个字符 0 次或 1 次。
- `|` : 逻辑“或”（Alternation）。
- `()` : 分组，用于限定 `|` 的范围或重复一段模式。

练习2: 匹配IP地址

任务：在 Tutorial 中，匹配 129.94.172.1 到 129.94.172.25

理解逻辑：
    前三段固定: 129\.94\.172\. 
    最后一段： 可以是1-9， 或者是10-19， 或者是20-25
    组合: ([1-9]|1[0-9]|2[0-5])

最终指令 ``` grep -E '129\.92\.172\.([0-9]|1[0-9]|2[0-5])' ```



### 深度理解（避坑指南）

1. 贪婪匹配 vs. 非贪婪匹配

笔记： ``` .*``` 会匹配尽可能多的字符
例子： 匹配HTML 标签 <a> test </a>

如果使用 <.*> 他会匹配第一个 < 到 > 之间的所有字符

解决方案: 如果使用[^>]*。 意思是匹配除了 > 以外的所有字符， 知道遇到第一个 > w 为止

正确练习 ： ``` <[^>]*>```

1. shell的特殊字符

为什么 grep <p> test.html 会报错：

 < > 是shell里面的重定向符号
 准则： 永远用单引号扩起你的正则表达式

 错误：``` grep <p>|<br> file ```

 正确：``` grep -E '<p>|<br>' file ```
