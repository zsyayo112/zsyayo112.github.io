## 命名规范

### 文件命名规则
```
[分类]-[主题]-[序号]-[描述].md
```

#### 示例：
- `COMP9044-刷题-01-学生选课数据处理.md`
- `COMP9044-Lab-01-简易版本控制系统.md`
- `0567-字符串的排列-滑动窗口陷阱分析.md`

### 各部分说明：
1. **分类前缀**：表明内容所属的大类
2. **主题**：具体的技术或课程名称
3. **序号**：同一主题下的编号（01, 02, ...）
4. **描述**：简短描述内容

### 特殊文件：
- `README.md`：目录说明和导航
- `BLOG-STRUCTURE.md`：结构规划文档

## 内容质量标准

### 文章结构要求

#### 技术学习系列文章结构（如Go-Learning）
1. **学习目标**：明确本篇文章要掌握的内容
2. **知识讲解**：系统讲解核心概念和原理
3. **代码示例**：提供完整可运行的代码示例
4. **实战练习**：设计练习题巩固学习效果
5. **总结回顾**：提炼关键知识点和学习收获
6. **下篇预告**：预告下一篇学习内容

#### 算法题解文章结构
1. **问题描述**：清晰说明要解决的问题
2. **解决方案**：详细讲解解决思路
3. **代码实现**：提供完整可运行的代码
4. **分析总结**：深入分析关键点和学习收获
5. **扩展思考**：提出相关问题和进阶学习方向

#### 课程学习文章结构
1. **题目描述**：完整呈现题目要求
2. **解题思路**：分析问题解决策略
3. **代码实现**：提供完整解决方案
4. **知识点总结**：提炼相关技术要点
5. **扩展应用**：思考其他应用场景

### 代码规范
1. **完整可运行**：提供完整的代码示例
2. **注释清晰**：关键代码添加注释说明
3. **测试用例**：包含测试代码或示例
4. **性能考虑**：讨论时间复杂度和空间复杂度

### 写作风格
1. **技术准确**：确保技术细节正确
2. **逻辑清晰**：步骤分明，推理严谨
3. **实例丰富**：使用具体例子说明抽象概念
4. **总结提炼**：每篇文章都要有明确的收获总结
